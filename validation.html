Employee, Client, Project, Subcontractor, Timesheet, Payroll, Leave, CICPA and Site all read the SAME rules from here. For each rule, decide whether it should Block the save, only show a Warning (user can still proceed), or Allow with Approval (saved, but flagged into a review queue below).

How this works: every module on this ERP loads erp-validation.js and calls a single CMV.enforce(ruleKey, violated, message) function before saving a record. That function reads the mode you set here and either blocks the save, asks the user to confirm, or lets it through while logging it to the Allow-with-Approval queue above — so all modules stay consistent without editing each portal separately.

Note on database-level constraints: this prototype runs entirely in the browser (localStorage), so there is no real database to attach a UNIQUE constraint to. This page is the equivalent control layer for that environment. When this ERP is migrated to a real database (e.g. Supabase/PostgreSQL), the same fields listed here should additionally get actual UNIQUE constraints / composite indexes at the schema level, plus created_at, created_by, updated_at, updated_by, deleted_at columns on every table so records are soft-deleted (Active/Inactive) instead of hard-deleted — this page defines exactly which fields those constraints should cover.
